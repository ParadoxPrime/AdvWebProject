JSON Rules

Rule 1: Key Syntax Rules
  • Keys must be strings.
  • Keys should be unique within an object.
  • Keys are case-sensitive.
Rule 2: Value Rules
  • Values can be strings, numbers, objects, arrays, booleans, or null.
  • Strings must be enclosed in double quotes.
  • Numbers can be integers or floating-point values.
Rule 3: Object Rules
  • Objects are unordered collections of key-value pairs.
  • Values can be any valid JSON data type.
Example:
{"name": "Jane Doe", "age": 32, "email": "jdoe@example.co.nz"}
Rule 4: Array Rules
  • Arrays are ordered collections of values.
  • Values can be any valid JSON data type.
Example:
["apple", "banana", "cherry"]
Rule 5: Common Mistake #1
  • Using single quotes instead of double quotes for strings.
  • Incorrect Example: {'name': 'John Doe'}
  • Correct Example: {"name": "John Doe"}
Rule 6: Common Mistake #2
  • Adding trailing commas after the last key-value pair in an object.
  • Incorrect Example: {"name": "John Doe", "age": 30,}
  • Correct Example: {"name": "John Doe", "age": 30}
